HEALTH CHECKS Y MONITOREO - ORBINODO ENTERPRISE v1.0
=======================================================

OBJETIVO
--------
Detectar de forma segura si Fastify/Vercel y PostgreSQL/Neon estan disponibles.
No se transmiten contrasenas, cookies, tokens, hashes, DATABASE_URL ni respuestas internas.

ENDPOINTS
---------
GET /api/live es liveness. Responde 200:
{ "status": "ok", "service": "api" }

No consulta PostgreSQL. Si responde, la Function/Fastify puede atender solicitudes.

GET /api/health es readiness. Responde 200:
{ "status": "ok", "database": "available", "serverTime": "ISO-8601" }

Consulta CURRENT_TIMESTAMP en PostgreSQL. Si Neon no responde devuelve 503 DATABASE_UNAVAILABLE
sin revelar SQL, ruta, stack trace ni secretos.

CONFIGURACION SEGURA
--------------------
Cree un archivo local ignorado por Git llamado .env.monitor.local con:

ORBINODO_MONITOR_URL=https://orbinodo-demo.vercel.app
ORBINODO_MONITOR_TIMEOUT_MS=10000
# Opcional: URL HTTPS privada del canal de alertas aprobado.
# ORBINODO_MONITOR_ALERT_WEBHOOK_URL=https://servidor-aprobado.example/webhook

No agregue el webhook al repositorio, a .env.example, al frontend ni a Vercel si el monitor
se ejecuta desde otra plataforma. La URL del webhook nunca se imprime en los logs.
