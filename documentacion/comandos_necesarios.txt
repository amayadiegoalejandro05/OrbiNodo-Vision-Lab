COMANDOS NECESARIOS Y SU UTILIDAD

cd D:\01_ORBINODO
Entra en la carpeta del proyecto.

code .
Abre el proyecto en Visual Studio Code.

npm ci
Instala las versiones exactas de package-lock.json en otro computador.

npm run dev
Inicia el servidor local; se detiene con Ctrl+C.

npm run typecheck
Comprueba TypeScript sin generar archivos.

npm run lint
Analiza el código con ESLint.

npm run build
Comprueba tipos y genera dist. dist puede contener fotos privadas.

npm run preview
Muestra localmente la construcción existente en dist.

npm run check
Ejecuta lint, pruebas, tipos, build y verificación real del navegador.

git status
Muestra archivos nuevos o modificados sin cambiar nada.

git diff
Muestra cambios aún no preparados.

git diff --staged
Muestra cambios seleccionados con git add.

git add nombre-del-archivo
Selecciona un archivo; confirma antes que no sea una foto privada.

git commit -m "mensaje descriptivo"
Guarda un punto del historial local.

git log --oneline
Muestra el historial resumido.

PRECAUCIÓN
git push publica cambios y requiere autorización.
git reset --hard y git clean pueden eliminar trabajo.
npm update cambia dependencias; después ejecuta npm run check.
No uses git add . sin revisar git status.
No agregues --host a Vite para una demostración local normal.

COMANDOS DE LA FASE 6

npx vercel
Crea o enlaza el proyecto y genera una URL de vista previa. Aceptar Vite, el directorio actual y la configuración detectada; no cambiar dist manualmente porque vercel.json ya lo declara.

npx vercel env add VITE_DEMO_USERNAME
Registra el usuario en Vercel. Debe añadirse al menos para Preview y Production.

npx vercel env add VITE_DEMO_PASSWORD_SHA256

npx vercel --prod
Publica la versión de producción. Solo se ejecuta después de aprobar la URL Preview.

Importante: las variables VITE son visibles técnicamente en el código descargado por el navegador. Esta fase es una barrera básica para una demo pública, no autenticación segura.

COMANDOS PARA LOS DOS USUARIOS DE LA DEMO
=========================================

npm run auth:hash
Solicita primero el rol programador o jefe y después una contraseña. Devuelve el
hash SHA-256 con el nombre de variable correcto. No escribir la contraseña como
parte del comando ni copiarla en documentos.

Variables locales opcionales para una contraseña propia del Jefe:

VITE_DEMO_MANAGER_USERNAME=Jefe
Define el nombre exacto del segundo usuario. Distingue mayúsculas y minúsculas.

VITE_DEMO_MANAGER_PASSWORD_SHA256=hash_de_64_caracteres
Define el hash de la contraseña exclusiva del Jefe. Si falta, se reutiliza
temporalmente el hash del Programador.

npx vercel env add VITE_DEMO_MANAGER_USERNAME
Registra en Vercel el nombre del usuario Jefe para el entorno que se seleccione.

npx vercel env add VITE_DEMO_MANAGER_PASSWORD_SHA256
Registra en Vercel el hash de la contraseña del Jefe. Se pega solamente el hash,
nunca la contraseña original.

npx vercel --prod
Construye y publica los cambios y las variables configuradas en producción. No
debe ejecutarse hasta autorizar expresamente la actualización de Vercel.

Para comprobar localmente después de cambiar .env.local:

npm run dev
Reinicia Vite para que vuelva a leer las variables. Una pestaña que conserve una
sesión anterior debe cerrar sesión y entrar nuevamente con el usuario que se
quiere verificar.

Instala el complemento oficial que dibuja puntos interactivos dentro del panorama
y abre fichas laterales. Se fija la versión 5.15.0 para que coincida exactamente
con @photo-sphere-viewer/core y @photo-sphere-viewer/virtual-tour-plugin.

No ejecutar npm audit fix --force automáticamente. Puede introducir cambios
incompatibles en dependencias. Los avisos de npm deben revisarse por separado
antes de decidir actualizaciones.
